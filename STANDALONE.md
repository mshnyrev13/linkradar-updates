# Автономное приложение LinkRadar

Нативный интерфейс Qt/PySide6: собственное окно, без HTTP-сервера, localhost, браузера и Terminal. Python и Qt включены в поставку.

Актуальные изменения 2.10.0 — [RELEASE-NOTES-2.10.0.md](RELEASE-NOTES-2.10.0.md),
результаты проверки — [VALIDATION.md](VALIDATION.md). Ниже также сохранена история
прежних компоновок; текущий контракт 2.10.0 имеет приоритет.

В 2.10.0 карточки слева всегда относятся к конечному серверу. Выбор hop меняет
графики; его Avg/Min/Cur/PL остаются в строке таблицы. Текущий RTT и jitter не
меняются от агрегации графика. Интервал узла и длительность полного цикла — в
подсказке: TTL-зонды выполняются последовательно. ICMP Unreachable конечного
ping считается неуспешной пробой, локальная ошибка/DNS — отдельно от PL.

HTTP-тест скорости привязан к выбранному адаптеру; смена адаптера отменяет тест.
Auto использует маршрут ОС, DNS — системный резолвер. Настройки адаптера,
интервала, масштаба и размера окна сохраняются без измерений. Отсутствующий
адаптер не заменяется Auto. В выборе сервера есть текущий шлюз.

TXT сохраняется в рабочем потоке, при отмене старый файл остаётся целым.
Предупреждение о неполноте означает реальную ошибку записи части данных.
Закрытие показывает «ЗАВЕРШАЕМ…» до остановки задач и очистки базы. Сохранённые
вручную TXT, безопасные настройки, ключ IPC и ограниченный технический журнал
ошибок остаются; журнал событий, измерения и служебные stdout/stderr очищаются.

- `apps/VCS-Network-Watch-macOS.dmg`: macOS 15+, Apple Silicon. Перенесите LinkRadar.app в Applications и откройте её. Обычное закрытие окна останавливает сбор и очищает данные, включая фоновый движок.
- `apps/VCS-Network-Watch-Windows-x64.zip`: Windows 10/11 x64. Распакуйте всю папку и запустите LinkRadar.exe. Готовый ZIP на Windows не запускался; комплектность runtime, Qt и формат EXE проверены на Mac. Исходники (ветка feature/stream-tab) запущены на Windows 10.

Введите сервер или RTMP/RTMPS URL, выберите интервал 0,5 / 1 / 2 секунды и нажмите ▶. Кнопка меняется на ⏸: пауза сохраняет сессию и историю, повторный ▶ продолжает ту же сессию. Смена интервала сохраняет историю. Изменение сервера применяется после нажатия ▶ и запускает новую историю. Изменение периода графика не меняет интервал опроса. Маршрут всегда открыт; клик по узлу выбирает его график. Наведение на график показывает время и миллисекунды. Колесо меняет период. Журнал событий очищается при новой сессии и обычном закрытии приложения.

Проверяются ICMP RTT и маршрут. Jitter — EWMA соседней разницы ICMP RTT, а не jitter медиапотока. Карточки OK/ALARM и RTMP удалены; автоматическая TCP-проверка RTMP больше не запускается. По ICMP нельзя судить о качестве видео; фактические счётчики и переподключения OBS/vMix читаются отдельно во вкладке Stream. Потери ответов промежуточного узла не доказывают потери транзитного трафика.

Данные: macOS `~/Library/Application Support/VCS Network Watch`, Windows `%LOCALAPPDATA%\VCS Network Watch`; фоновая служба Windows — `%ProgramData%\VCS Network Watch\<id>` (запись только SYSTEM и администраторам, см. «Фоновый режим»). Системные ping/traceroute/tracert и разрешения сети нужны для сетевых проб. Пользовательские замеры в пакеты не включены.

Пакеты без Developer ID/Authenticode и нотарификации. Mac: Python 3.12.14, PyInstaller 6.22.3 windowed onedir, PySide6 6.12.0. Windows: официальный embedded Python 3.13.12 x64, PySide6 Essentials 6.12.0, GUI launcher Zig 0.13, запускающий pythonw.exe без консоли. PySide6/Qt распространяются по LGPLv3, уведомления включены в пакеты.

Исходники интерфейса: desktop.py. Движок: server.py, route_engine.py, packet_tools.py. Старый веб-интерфейс остаётся доступным для разработки; автономные пакеты используют desktop.py напрямую.

## Три колонки диагностики — 2.9.1, тестовая компоновка

Слева остаётся управление и основные показатели. Маршрут перенесён в центр, временные графики jitter и RTT — вправо. Round Trip (ms) находится под маршрутом. Ширина двух правых колонок регулируется горизонтальным разделителем, вертикальное изменение окна её не сбрасывает. Высота маршрута и блока временных графиков общая; уменьшается число видимых hops, оставшиеся доступны прокруткой. Верхние Graphene и захват не переставлены. Начальная ширина окна увеличена до 1440 px с учётом ширины экрана; минимальные размеры сохраняют читаемость. Это заменяет прежнюю вертикальную компоновку и пропорцию 1 : 1 : 1,4.

## Актуальное поведение 2.8.2 — macOS без Wireshark

Приложение из Applications проверяет доступ к BPF независимо от состояния фонового движка. Если доступа нет, встроенный установщик запрашивает подтверждение администратора, добавляет только запускающего пользователя в `access_bpf` и устанавливает собственный root-owned helper и задачу launchd для прав `/dev/bpf*` при загрузке и изменениях `/dev`. Python/Qt и пользовательский код приложения от root не запускаются. При уже настроенном доступе запрос пропускается. Отмена сохраняет обычную работу ping; для обновления членства группы может потребоваться повторный вход в учётную запись или перезагрузка.

Запуск из исходников и тестовые режимы ничего не устанавливают. Захват пакетов по-прежнему запускается только кнопкой. Подробности и удаление — [README-macOS.md](README-macOS.md). Удаление собственного helper не удаляет общую группу `access_bpf` и членство пользователя, поскольку они могут использоваться другими программами. Npcap нужен только Windows и отдельно устанавливается там.

## Актуальное поведение 2.9.0 — вкладка Stream, графики, значок Windows

Окно разделено на вкладки «Сеть» (прежний интерфейс) и «Stream». Подпись выбора адаптера — «Адаптер».

Графики выше: Graphene, маршрут и графики задержки делят высоту в пропорции 1 : 1 : 1,4 (`BLOCK_WEIGHTS` в desktop.py); jitter : RTT = 2 : 5; больше делений шкал при большей высоте. Окно по умолчанию — до 980 px, но не больше 94% высоты экрана. Это заменяет равную начальную высоту блоков из 2.8.0; ручные разделители сохранены. Минимальная высота окна на Windows ≈ 852 px (вкладки добавили ~24 px).

Вкладка Stream читает OBS (obs-websocket 5), vMix (XML API и открытое окно Statistics), TCP-соединения процессов OBS/vMix/FFmpeg (Windows, ESTATS от администратора) и NDI mDNS. Таблица потоков, графики битрейта, потерь кадров/с, RTT и congestion выбранного потока, таблица vMix Statistics с Δ за секунду, журнал событий, отчёт для провайдера (копировать/TXT) с сетью вкладки «Сеть». Запуск вручную ▶ / ⏸. История — RAM, до 12 часов, очистка при закрытии. Ключи потоков, пароли и параметры SRT не выводятся. Подробно и ограничения: [STREAM.md](STREAM.md).

Столбцы таблиц Stream меняются перетаскиванием и масштабируются с окном в пропорциях пользователя; отчёт — кнопки «Копировать» и «Сохранить TXT…».

Windows: окно получает собственный значок и группу на панели задач (AppUserModelID `VCS.NetworkWatch.Desktop`). Фоновый движок закрывает SQLite при штатной остановке (раньше файл базы оставался занятым).

## Актуальное поведение 2.8.1 — адаптер для ping и маршрута

Выбранный вручную адаптер используется для ping и ICMP-маршрута. Смена адаптера переключает новые пробы без сброса истории и сохраняет паузу; запоздалые ответы предыдущего адаптера отбрасываются. При отключении выбранного адаптера показывается недоступность, перехода на Wi-Fi или другой маршрут нет. «Автоматически» использует маршрут ОС. Для ping и маршрута LLDP не нужен. Тест скорости и системный DNS пока используют маршрут/резолвер ОС.

В macOS ручной выбор использует непривилегированный ICMP datagram socket с `IP_BOUND_IF` / `IPV6_BOUND_IF` и исходным адресом выбранного интерфейса. RTT измеряется от отправки до получения соответствующего ICMP-ответа по монотонным часам, без времени запуска утилиты. Маршрут использует последовательные TTL/Hop Limit от 1 до максимума, один зонд на hop. Проверяются ID/sequence и исходный пакет в ответах Time Exceeded; посторонние ответы не учитываются.

В Windows ручной выбор использует `IcmpSendEcho2Ex` / `Icmp6SendEcho2` с исходным адресом выбранного активного адаптера, TTL/Hop Limit и RTT из Windows ICMP API. Трассировка выбранного адаптера посылает один зонд на hop; в автоматическом режиме сохраняется системный tracert с тремя зондами. Состояние адаптера и наличие подходящего IPv4/IPv6 проверяются перед пробой и каждым hop. В режиме Auto IP выбирается адрес цели, для семейства которого на выбранном адаптере есть адрес. Таблица маршрута после смены адаптера ждёт новые hop-пробы; старые данные остаются в экспорте. Jitter не соединяет соседние измерения разных исходных адаптеров/адресов. Системная таблица маршрутизации не изменяется.

Нужен обновлённый фоновый движок с capability `bound_interface`. После замены приложения на Mac перезагрузите компьютер, если служба уже установлена. На Windows повторно запустите `Install background.cmd` из нового ZIP. Проверены 113 тестов на Mac; фактическое переключение Wi-Fi/USB на пользовательском оборудовании и выполнение Windows runtime в проверку не входили.

## Актуальное поведение 2.8.0 — хранение, очистка и компоновка

Нативное приложение и системный фоновый движок сохраняют измерения в `network.sqlite3` в каталоге данных, указанном выше. В таблицах ping, hop-проб, трассировок, событий и дополнительных данных остаются последние 12 часов: старые записи удаляются автоматически при сборе и на паузе. Дополнительные данные включают сетевую конфигурацию, точки Graphene и результаты скорости. Состояние активной сессии сохраняется для продолжения после паузы. Это скользящее окно, сбор не перезапускается раз в 12 часов. Освободившиеся страницы SQLite используются повторно; файл базы может сохранять ранее достигнутый размер во время сессии.

Обычное закрытие приложения сначала останавливает ping/traceroute, Graphene, LLDP, скорость и захват. Затем удаляет все записи базы, включая предыдущие сессии, выполняет VACUUM и усечение WAL, очищает `service-out.log` и `service-error.log`, а также данные в памяти. Если завершить сбор и очистить данные не удалось, окно остаётся открытым с сообщением об ошибке. Уже сохранённые пользователем TXT-экспорты не удаляются. Ключ доступа `service.key`, файлы блокировки и настройки службы сохраняются (на Windows служба создаёт новый ключ при каждом своём запуске). Служба остаётся установленной и работает без активного мониторинга. После нового открытия история пуста. При аварийном завершении, принудительном уничтожении процесса или отключении питания обработчик закрытия не гарантируется.

Журнал ошибок — отдельно от измерений. Это технические сбои приложения: непредвиденные исключения с трассировкой стека, ошибки потоков измерений, IPC службы, Qt (critical/fatal), чтения Graphene, LLDP, захвата, теста скорости и dumpcap. Измерений, пакетов и событий сессии в журнале нет. Файлы в папке данных:
- `errors.log` — окно приложения; `errors-service.log` — фоновая служба; `errors-web.log` — прежний веб-режим;
- `crash.log` / `crash-service.log` — аварии самого Python или Qt (faulthandler: только файл и строка, без значений).

Политика хранения:
- записи старше 12 часов удаляются при запуске и не реже раза в 10 минут при записи;
- размер — до 512 КБ плюс одна ротированная копия (`.1`); `crash*.log` удаляется при запуске, если он старше 12 часов или больше 256 КБ;
- перед записью из URL убираются логин, пароль, путь (у RTMP остаётся приложение), query и fragment; значения `key`, `password`, `token`, `streamid`, `passphrase`, `cookie`, `Authorization` и ключи `live_…` маскируются. Хосты и IP остаются для диагностики;
- журнал переживает обычное закрытие окна, чтобы причину сбоя можно было найти после перезапуска; через 12 часов он исчезает сам. Удалить раньше можно вручную;
- на macOS/Linux файл создаётся с правами 600. Повторяющиеся ошибки циклов опроса (сетевая конфигурация, LLDP, Stream) пишутся один раз, пока текст не изменится.

Кнопка «Журнал ошибок» внизу вкладки «Сеть» открывает `errors.log`. Журнал службы на macOS принадлежит root и открывается отдельно; на Windows он лежит в папке службы в ProgramData и читается только администратором. `service-out.log`/`service-error.log` (stdout/stderr службы macOS) по-прежнему очищаются при закрытии; трассировки туда выводятся уже без секретов.

Экспорт TXT содержит только данные, которые ещё находятся в 12-часовом окне. При остановке/паузе захвата его история по-прежнему ограничена 120 секундами в памяти; payload не записывается в SQLite, TXT или служебные логи.

Кнопка «Тест» и результат расположены внизу левого столбца под показателями, в одной строке. При открытии панель «Пакеты» имеет минимальную высоту и пустую таблицу с местом минимум для пяти строк; захват запускается вручную. Graphene, маршрут и временные графики получают одинаковую начальную высоту и равномерно растут с окном. Активный захват участвует в распределении; его высоту можно увеличить разделителем.

После замены приложения на Mac с уже установленным движком один раз перезагрузите компьютер. На Windows повторно запустите `Install background.cmd` из нового ZIP. Интерфейс 2.8.0 не подключается к движку без возможностей очистки и ограничения 12 часов.

Проверки: 99 тестов на Mac, в том числе очистка всех таблиц/служебных логов, сохранение экспорта/ключа, удаление старых данных на паузе, очистка через IPC и защита от запоздалых результатов. Запуск Windows runtime не проверен.

## Сетевая конфигурация, LLDP и скорость — 13 октября 2026

При открытии приложения автоматически читаются активные интерфейсы, эффективный MAC, IPv4/MASK, шлюз и DNS. По умолчанию выбран интерфейс маршрута по умолчанию; можно выбрать Ethernet вручную. Конфигурация перечитывается каждые 10 секунд, LLDP слушается постоянно в фоне. Данные предыдущего интерфейса сбрасываются, объявления истекают по TTL коммутатора.

Switch и Port берутся из LLDP System Name/Chassis ID и Port ID. VLAN — только Port VLAN ID (PVID) из IEEE 802.1 TLV. Если коммутатор не передал PVID, показано «—»: адрес подсети и теги постороннего трафика не используются для угадывания VLAN. LLDP не требует подключения к коммутатору и не отправляет запросы; захватывается только EtherType LLDP, без хранения прочих пакетов. Объявления часто приходят раз в 30–60 секунд; Wi-Fi, VPN и коммутатор с отключённым LLDP могут ничего не передавать.

На Mac используется системная libpcap; необходим штатный доступ пользователя к BPF (например, существующая настройка ChmodBPF). Начиная с 2.8.2 приложение предлагает собственную настройку BPF с подтверждением администратора (см. актуальный раздел выше); весь интерфейс от root не запускается. На Windows нужен установленный Npcap и разрешение захвата. Npcap — отдельный системный драйвер, в ZIP не включён; Python включён, Wireshark не нужен. Без прав/драйвера локальные сетевые поля и прочие функции работают, в строке LLDP показана причина.

Кнопка «Измерить скорость» запускает загрузку и отдачу через тестовые CDN-серверы интернетометра Яндекса: конфигурация https://yandex.ru/internet/api/v0/get-probes, четыре параллельных HTTPS-потока, 15 секунд измерения и 3 секунды прогрева на направление. Передаются только сгенерированные случайные блоки; личные файлы, cookies и телеметрические отчёты не отправляются. TLS проверяется по встроенному CA bundle certifi. В отдаче считаются только подтверждённые сервером полные блоки; скорость — полезные биты / время, в десятичных Мбит/с. Ошибка не превращается в ноль или фиктивный результат.

Это собственное HTTP-измерение по принципу интернетометра, а не точная копия его алгоритма. API/CDN Яндекса не является гарантированно стабильным контрактом: при изменении/блокировке сервисов замер может не пройти. Результат относится к CDN, а не к выбранному RTMP-приёмнику. Ограничение трафика — около 8 ГиБ на направление плюс завершающиеся блоки; результат короткой/частичной выборки помечается. Тест запускается только кнопкой и отменяется повторным нажатием. Он нагружает канал и может влиять на эфир: активный тест отмечен в строке состояния, журнале и синей областью на графике.

macOS может вернуть скрытый текущий MAC `02:00:00:00:00:00`. Он не отображается как настоящий: при доступности показывается аппаратный MAC адаптера (с подсказкой), иначе «—». Название сетевого порта добавлено к системному ID интерфейса. Для выбранного адаптера используется его scoped DNS и шлюз, если ОС их предоставила.

## Скорость и маршрут — обновление 13 октября 2026

Данные Graphene и выбор порта живут в памяти этой сессии; при закрытии удаляются. Текущий admin/oper Up/Down порта не выводится: счётчики сами по себе не доказывают состояние линка.

### Сон, блокировка и выход из учётной записи

При активном сборе автоматически удерживается система от обычного сна: macOS caffeinate -i, Windows SetThreadExecutionState. Экран может гаснуть, блокировка экрана не останавливает сбор. Принудительный сон, закрытая крышка со сном, выключение компьютера или недоступная сеть останавливают физическую возможность отправлять пакеты; такие промежутки не заполняются вымышленными измерениями.

Для продолжения ping/traceroute после закрытия окна и выхода из учётной записи установите фоновый движок один раз. Нужны права администратора. На macOS 2.5.1 приложение автоматически предлагает системную установку при первом открытии из Applications; потребуется стандартное подтверждение macOS с паролем администратора. На Windows установка остаётся ручной.

macOS: замените приложение в Applications и откройте его. При первом запуске автоматически выполняется встроенный `install-background-mac.command` и macOS запрашивает пароль администратора. LaunchDaemon работает в системном домене от вашего пользователя, без GUI и внешнего Python. При следующих открытиях приложение подключается к существующей службе, не перезапуская её или текущую сессию. При сборе показано «ФОН». Если отменить авторизацию, откроется обычный режим; установка повторится при следующем открытии. При недоступной установленной службе второй движок не запускается. При открытии прямо из DMG показана просьба перенести приложение в Applications. Скрипт из DMG можно использовать вручную; он также не перезапускает работающую службу. Для удаления используйте `remove-background-mac.command` (при последующем открытии приложение снова предложит установку).

Windows: распакуйте ZIP в постоянную папку, закройте приложение, запустите `Install background.cmd`. Скрипт запрашивает UAC и создаёт задание Task Scheduler при старте системы, с учётной записью SYSTEM и встроенным Python: `desktop.py --engine-service --user-sid <ваш SID>`. Исполняемые файлы службы копируются в защищённую папку Program Files; доступ к локальному named pipe разрешён SYSTEM, администраторам и вашему SID. Программа подключается к движку через локальный канал с аутентификацией. Для удаления используйте `Remove background.cmd`. Выполнение на Windows пока не проверено.

Данные службы Windows (аудит, п. 3): служба работает от SYSTEM, поэтому её файлы не лежат в папке пользователя — иначе junction или жёсткая ссылка заставили бы SYSTEM создать или обнулить чужой файл. Папка — `%ProgramData%\VCS Network Watch\<id>`, `<id>` — 16 hex SHA-256 от SID пользователя (`service_paths.py`; установщик считает так же). Служба при каждом запуске сама создаёт папки, открывает их без следования ссылкам и через тот же дескриптор ставит владельца SYSTEM и защищённый DACL: SYSTEM и администраторы — полный доступ, пользователь — только просмотр папки и чтение `service.key`. Ключ создаётся заново при каждом запуске. Перед открытием файлов службы (база, WAL, блокировка, ключ, журналы) проверяется, что это обычный файл с одной ссылкой и владельцем SYSTEM/администраторы; иначе удаляется только имя, без цели. База службы окну недоступна: сетевые параметры, скорость, точки Graphene, события теста скорости и TXT-экспорт окно передаёт и получает через канал (команды `record`, `event`, `export`; служба принимает только эти виды данных и существующие сессии). Обычный режим без службы по-прежнему хранит базу в `%LOCALAPPDATA%`.

Переход с 2.8.1 и раньше: повторно запустите `Install background.cmd` из нового комплекта. Он снимает прежнюю задачу (данные в `%LOCALAPPDATA%`) и её копию в Program Files, ставит новую, затем уже без прав администратора удаляет из вашей папки файлы прежней службы (`service-user.sid`, `service.key`, `service.lock`, журналы службы, базу). Пока прежняя служба работает, новое окно предупреждает и не запускает второй движок. `Remove background.cmd` снимает обе задачи и удаляет папку службы в ProgramData (`rmdir /s` не заходит в junction).

Сервис не запускает веб-сервер. IPC использует Unix socket на Mac и named pipe на Windows, приватный ключ текущей установки; shell-команды через IPC не принимаются. При повторном открытии окна активная сессия подключается, события не очищаются до новой сессии. Скорость, LLDP и чтение Graphene выполняет интерфейс: при закрытом окне их сбор не продолжается; фон сохраняет ping/traceroute и события движка. Служба с capability `session_data` (Windows и обновлённая macOS) принимает эти данные через канал; к прежней macOS-службе окно по-прежнему пишет в общую базу.

## Версия 2.6.1 — реальный локальный захват пакетов с паузой

Под Graphene размещена компактная панель «Пакеты». Захват никогда не запускается при открытии приложения, появлении LLDP, старте ping или переподключении кабеля. Кнопка ▶ / ⏸ запускает, приостанавливает и продолжает захват; отдельная ■ завершает его. Пауза сохраняет текущую историю и выбранный пакет, пока им не исполнилось 120 секунд. Pcap handle на паузе закрывается; продолжение открывает новый handle того же адаптера, не добавляя пакеты, пришедшие во время паузы, и не очищая сохранившуюся историю. В текущей 2.9.1 адаптер выбирается строго верхним селектором (его `local.capture`); LLDP для захвата не требуется. При отключении или смене локального адаптера текущий захват, включая приостановленный, останавливается; следующий запуск — только вручную. Исчезновение LLDP или изменение объявленного порта на том же адаптере не прерывают локальный захват. В заголовке показано имя адаптера. Остановка и закрытие GUI освобождают pcap handle, фоновая служба захват не продолжает.

Это pcap/Npcap-трафик локального адаптера (входящий, исходящий, broadcast/multicast и доступные зеркалированные кадры), а не запрос пакетов к коммутатору. LLDP задаёт соответствие интерфейса порту, но не даёт удалённый packet capture. Для всего чужого трафика нужен настроенный SPAN/mirror. Захват открывается promiscuous, не меняя конфигурацию коммутатора. Mac использует системную libpcap и доступ к BPF; Windows требует установленного Npcap и прав захвата. Wireshark и отдельный Python не нужны, драйвер Npcap в ZIP не включён.

Таблица показывает реальное время кадра, источник/назначение, протокол, исходную полную длину и информацию. Разбор Ethernet/VLAN, IPv4/IPv6 (в том числе extension/fragment headers), TCP/UDP, ICMP/ICMPv6, ARP, LLDP и EAPOL. TCP — фактические флаги, Seq, Ack, Win; экспертный разбор retransmission/lost segment из Wireshark не эмулируется. Клик по пакету показывает hex/ASCII снимка. Сохраняются первые 256 байт кадра — заголовки и начало данных; полный payload не сохраняется. Размер и скорость рассчитываются по исходной длине кадра, а не по усечённому снимку. Мбит/с и пак/с — последняя завершённая секунда. Счётчик пропусков libpcap относится к захвату с начала текущего запуска, не к измеренным сетевым потерям.

История — только RAM, без PCAP, SQLite, журналов и включения пакетов в TXT сессии. Кадры/агрегаты автоматически удаляются по монотонному возрасту не более 120 секунд, в том числе на паузе и после Стоп. На macOS используется mach_continuous_time, учитывающий время сна; коррекция системных часов не продлевает историю. Дополнительный предел — 50 000 кадров и оценка 32 МиБ для raw/метаданных; при высокой нагрузке старые кадры удаляются раньше, показывается «буфер ограничен». Скорость/число наблюдённых кадров считаются независимо от удаления строк по памяти. При новом ▶ после Стоп прежняя история захвата очищается; ▶ после паузы продолжает ту же сессию. Когда нет активного захвата и истории, таблица убирается, остаются компактный заголовок и кнопки; при захвате появляется таблица с прокруткой. Позиция просмотра сохраняется при поступлении новых кадров, выбранный пакет исчезает после истечения срока.

Проверены 87 тестов, включая искусственные Ethernet/TCP/VLAN/IPv6-кадры, остановку/закрытие pcap, отсутствие автозапуска, точное соответствие LLDP-интерфейса, монотонные 120 секунд на паузе и после Стоп, лимиты памяти/пакетов, паузу/продолжение с сохранением истории, быстрые переключения с отбрасыванием кадров старого handle, GUI-порядок и сохранение остальных функций. Символы системной libpcap проверены без открытия захвата. Реальный пользовательский трафик при сборке не захватывался. Windows runtime пока не выполнялся.

## Версия 2.6.2 — контрастные кнопки и растягиваемая таблица захвата

Стандартная иконка Qt для доступной кнопки ▶ могла рисоваться чёрным на тёмном фоне; серый отключённый ■ при этом был виден лучше. Кнопки захвата теперь имеют собственные светлые векторные значки: ▶ / ⏸ на синем фоне и отдельная ■ на нейтральном. Обе всегда занимают фиксированное место. В текущей 2.9.1 после выбора доступного USB-адаптера доступна ▶ без ожидания LLDP, а ■ отключена до запуска захвата; автозапуск не добавлен.

Панель пакетов растягивается по вертикали разделителем под ней; прежний предел высоты 235 px убран. Основное окно также можно растягивать за нижнюю границу. При первом появлении пакетов панель получает компактную высоту, затем пользователь может выделить ей больше места. Чередующиеся строки и выделение имеют явный тёмный фон, чтобы бирюзовый текст UDP не попадал на белую полосу системной темы. Проверены 90 тестов, включая USB/LLDP в компактном окне, контраст значка, растягивание панели и фон строк.

## Версия 2.6.3 — отключение и возврат USB

При исчезновении вручную выбранного USB-адаптера сохраняются его ID и выбор: в списке появляется «нет подключения», вместо сброса на «Автоматически». После возвращения адаптера обнаружение LLDP продолжается именно на нём. Отложенные результаты от другого адаптера игнорируются. Активный захват при потере источника останавливается; оставшиеся строки помечены «последние пакеты» и удаляются в пределах 120 секунд. Возврат адаптера сам по себе не запускает захват: в текущей 2.9.1 после обнаружения адаптера становится доступна ▶ без ожидания LLDP, нужен ручной запуск. Обновление сетевой конфигурации — до 10 секунд, ожидание нового LLDP зависит от интервала объявлений коммутатора (часто 30–60 секунд).

Повторный Stop не может вернуть уже завершившийся захват в «Завершаем…» в коротком промежутке между очисткой и выходом рабочего потока. Stop доступен, пока поток захвата действительно работает; состояние кнопок не зависит только от наличия LLDP. Проверены 93 теста, в том числе остановка поступления кадров, сохранение последних строк, возврат ▶ после нового LLDP без автозапуска и сохранение выбора USB.

## Версия 2.7.2 — одинаковые блоки и задержки слева

При открытии Graphene, маршрут и временные графики имеют одинаковую высоту. Изменение размера окна снова распределяет высоту поровну; ручное перетаскивание разделителей действует до следующего ресайза. При открытой таблице пакетов её блок также получает равную высоту. Без захвата панель остаётся компактной. Минимальная высота окна учитывает читаемость графиков и элементов управления, чтобы они не перекрывались. Hops, не поместившиеся в таблицу, доступны прокруткой; таблицу можно увеличить разделителем.

Под Ping без ответа находятся карточки «Средняя задержка» и «Максимум» в миллисекундах за выбранный период. При выборе hop они показывают статистику его графика; источник указан в подсказке. Строка с этими значениями над графиком убрана. Наведение показывает точное время, RTT и jitter в подсказке графика.

96 тестов прошли, включая равенство начальных размеров, равномерный рост, ручной ресайз и сохранение всех hops. Запуск Mac-сборки и целостность пакетов проверены; запуск на Windows пока не проверен.

Справа вверху рядом с Copy находится шестерёнка: «Журнал событий» (показать/скрыть), «Журнал ошибок» и «Экспорт TXT». Отдельных кнопок этих действий внизу больше нет. Измерение скорости — в одной строке внизу левого столбца диагностики.

Компактное окно: левый столбец 180 px, минимальный размер 900×640, начальный — до 1100×720 с учётом доступного экрана. При узком маршруте скрываются вспомогательные Count/Name; имя узла и число проб доступны по наведению на IP. Avg, Min, Cur, PL% и график Min–Max остаются видимыми. При расширении Count/Name возвращаются. Скорость внизу столбца запускается кнопкой «Тест», процент остаётся внутри неё.
