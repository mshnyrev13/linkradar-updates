# LinkRadar 2.10.5 — последовательные циклы стабилизации

21 октября 2026, поверх 2.10.4. Прежние изменения сохранены. Рабочая app/служба,
пользовательский профиль и настройки ОС не менялись; установки/публикации нет.
Все измерительные стенды этого этапа синтетические и используют private profiles.
Ход циклов: [CYCLES.md](https://github.com/mshnyrev13/vcs-network-watch).

## Исправления по циклам

1. **Запись Graphene.** При 50k cache прежняя логика полностью забывала ACK.
   54 000 исходных точек + 9 свежих + неизменный snapshot давали 108 009 попыток
   записи вместо 54 009. Теперь ACK cache очищается по 12-часовому сроку, старые
   входящие точки за пределами срока не записываются. Неуспешная запись не
   подтверждает cache и повторяется с теми же ключами.
2. **Локальный GUI.** Без службы JSON/SQLite запись выполнялась в Qt-потоке.
   Теперь локальный/удалённый режим используют IOQueue, JSON готовится вне
   writer mutex, транзакции локальной записи ограничены 512 строками. Периодическая
   очистка также поставлена в очередь. Барьер экспорта ждёт всей записи; close
   ждёт через timer, затем очищает данные. Прежний wait(20) означал 20 мс, не 20 с;
   он не объявлен подтверждённым длительным зависанием.
3. **Stream и маршруты.** Клавиатурное выделение теперь выбирает соответствующий
   поток/hop и график, как мышь. Программное обновление таблицы не запускает
   рекурсивные пользовательские действия. Состав блоков и кнопки сохранены.
4. **Журналы.** На rollover 5000 событий Stream терял выделение текста и пересоздавал
   документ. Новый общий log helper меняет только удалённый префикс/добавленный
   хвост, сохраняет курсор и видимое сообщение, включая переносы строк. Поиск
   overlap линейный и корректен при повторяющихся строках; используется и сетью.
5. **Таблица пакетов.** Каждое обновление сбрасывало Qt row identities. Теперь append/
   expiry используют insert/remove, другой или разорванный буфер — безопасный
   reset. Поиск выбранного пакета/якоря бинарный, без словаря на 50k строк. Выбор
   стрелками обновляет детали, сигналы служебного восстановления выбора блокируются.
   Форматирование timestamp выполняется только для столбца времени.
6. **Перегруженная очередь.** queue.Full при подготовке экспорта ранее уходил
   необработанным исключением в Qt-slot. Теперь объясняется занятость; файл не
   создаётся/не перезаписывается, действие остаётся доступным для повторения.

Числовые формулы RTT/PL/jitter, привязка адаптера, интервалы, ручной захват,
исходные история/TXT и правила очистки сохранены. В пакеты не добавлены сетевые
запросы, SNMP, запись в OBS/vMix или новые системные разрешения.

## Измерения до/после

Один Mac, отдельные процессы и фиксированные синтетические данные. Это не
сравнение всей загрузки реальной пользовательской сессии.

| Стенд | До | После |
| --- | ---: | ---: |
| Попыток записи Graphene, 54k + 9 изменений + повтор | 108 009 | 54 009 |
| Максимальный heartbeat gap в этом стенде | 478,578 мс | 71,931 мс |
| GUI handler первой записи | 212,848 мс | 33,338 мс |
| Packet refresh + paint, 50k, 900×300, медиана 50 обновлений | 19,6579 мс | 5,9677 мс |
| 60k запросов display ячеек | 6334,7357 мс | 1151,1018 мс |

Все 54 009 уникальных строк в обоих record стендах реально присутствовали в SQLite.
Максимальный gap отражает и начальную обработку большого ряда; ожидание I/O не
перенесено в GUI под другим именем. Исходные JSON/команды/стенды:
[round4/README.md](https://github.com/mshnyrev13/vcs-network-watch).

## Контрольный проход и границы вывода

- 13 новых проверок, общий набор **344 теста OK, 11 skipped, 33,627 с**.
- 2000 seeded сравнений log overlap с brute force и 400 seeded переходов packet
  model: append, expiry, другой capture, сохранение выживших row identities.
- Проверены TTL cache, retry частично успешной записи (600 уникальных строк),
  saturated queue/export, клавиатура, selection/scroll, close/clear.
- 8 состояний UI на 900×640 / 1100×760 / 1440×960; повтор при масштабе 150%.
- Совместный 120,24-секундный Qt/SQLite/Stream/Graphene/packet стенд: CPU 6,94%
  одного ядра, P99 heartbeat 33,05 мс, max 94,3 мс. Сохранены 54 207 из 54 207
  ожидаемых Graphene строк, ошибок I/O нет. Packet buffer 33 554 318 байт при
  лимите 33 554 432, 48 913 сохранённых кадров. После закрытия все шесть
  измерительных таблиц пусты.
- Peak RSS 188 694 528 байт; RSS рос при заполнении пакетного буфера. По короткому
  стенду нельзя заключить отсутствие утечки ночью. Не сравнивать этот CPU с
  другим составом нагрузки 2.10.3 или 2.10.4.

**Условие остановки:** контрольная матрица после четырёх циклов исправлений не
выявила новых существенных дефектов в доступных сценариях. Это не утверждение,
что больше никогда нельзя улучшить приложение. Приёмка собранной app и упаковки
фиксируется отдельно в VALIDATION.md и round4/README.md.

Windows runtime, чистый Mac/другой пользователь/новая установка, живые OBS/vMix,
реальный эфир и повторный ночной soak этим этапом не проверены. Нет Developer ID/
нотаризации и Windows publisher signature. При холодном большом обновлении остаются
короткие паузы порядка 100 мс. Security/speed stage не повторялся без новой причины.
