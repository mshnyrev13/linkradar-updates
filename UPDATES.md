# Обновления LinkRadar

Начиная с 2.10.6 приложение проверяет наличие новой стабильной версии при
открытии окна и затем каждые 6 часов. Проверка идёт в отдельном потоке,
не останавливает измерения и не отправляет историю, IP, MAC или сведения порта.
При отсутствии интернета автоматическая проверка молчит.

Если доступна новая версия, появляется компактная строка «Доступна LinkRadar …»
с кнопками «Скачать» и «Позже». Повторное уведомление об этой версии в том же
сеансе не появляется. Ручная проверка: «О приложении → Проверить обновления…»,
меню «Справка» на macOS или шестерёнка. Ручная проверка сообщает и об отсутствии обновлений,
и об ошибке доступа к каналу.

«Скачать» открывает страницу в обычном браузере. Приложение не скачивает и
не запускает установщики, не заменяет себя и не меняет службу. Сначала сохраните
нужный TXT, затем закройте старую версию и установите новый пакет. Уже выпущенные
2.10.5 и более старые версии нужно обновить вручную один раз: проверки в них нет.

## Единый публичный репозиторий

`mshnyrev13/linkradar-updates` содержит актуальные исходники, тесты, инструкции,
пакеты в Releases и latest.json. Токен GitHub на компьютере техника не нужен.
Старый vcs-network-watch сохраняет историю разработки до объединения.

Адрес канала: https://raw.githubusercontent.com/mshnyrev13/linkradar-updates/main/latest.json

Пример (версия и ссылка должны относиться к реально доступному выпуску):

```json
{
  "version": "2.10.6",
  "download_url": "https://github.com/mshnyrev13/linkradar-updates/releases/tag/v2.10.6"
}
```

Публичный Release содержит DMG, Windows ZIP и контрольные суммы: скачивание без
входа в GitHub. Исходники и тесты доступны публично в этом же репозитории. Для
распространения также поддерживается публичная ссылка Яндекс Диска. Не обновляйте
номер в канале раньше загрузки файлов.

## Выпуск следующей версии

1. Измените `VERSION` в `server.py`, проверьте тесты и соберите пакеты обеих платформ.
2. Опубликуйте DMG, Windows ZIP и контрольные суммы в Releases публичного канала;
   добавьте архив исходников в тот же выпуск.
3. Workflow `Update public version feed` сам обновит `latest.json` после публикации
   стабильного Release, если в нём есть оба установщика и SHA256SUMS.txt.
4. Прочитайте raw-адрес без авторизации и проверьте уведомление из предыдущей версии.

Workflow работает внутри публичного репозитория со штатным временным GitHub Token;
отдельный токен между репозиториями не нужен. Он пропускает черновики и prerelease,
проверяет наличие файлов и не снижает номер версии. При сбое запустите workflow
вручную через Actions после исправления выпуска. Workflow: .github/workflows/update-feed.yml.

## Ограничения и защита

Проверяются только версии `X.Y.Z` (не черновики, теги prerelease или коммиты).
Номера сравниваются по числам. Нет отката на более старую версию. Размер ответа
ограничен 16 КиБ; HTTPS проверяется через системное хранилище доверия и certifi,
перенаправления запрещены. Ссылки принимаются только на Releases основного
репозитория, публичного канала или публичную страницу Яндекс Диска; никакие команды не исполняются.
Источник проверки использует обычный маршрут ОС, не измерительный адаптер.
