# Аудит безопасности LinkRadar 2.10.1

21 октября 2026. Исходники и локальные сборки. Рабочая установка, службы,
системные разрешения и пользовательские данные не менялись. Публикация не выполнялась.

Аудит охватывает Python-модули, Mac/Windows установщики, локальный IPC,
сетевые парсеры, зависимости и упаковку. Это проверка указанных границ доверия,
не сертификат безопасности и не доказательство отсутствия всех уязвимостей.

## Модель доверия

- Сеть, LLDP, mDNS, ответы Graphene/OBS/vMix, содержимое пакетов и PCAP недоверенные.
- IPC требует ключа; GUI не получает права SYSTEM и не передаёт службе произвольный путь записи.
- Mac engine работает как обычный пользователь. Root выполняет фиксированную настройку launchd/BPF.
- Windows engine работает как SYSTEM; исполняемые файлы и данные защищаются отдельно.
- Установочный пакет должен быть получен из доверенного источника. Подпись издателя пока отсутствует.

## Находки и изменения

| ID | Приоритет / доказательство | Результат |
| --- | --- | --- |
| S01 | Критическая запись внешней базы; версия совпала | `certifi 2026.7.22` затронута GHSA-6q48-6c7w-9gw2 / PYSEC-2026-4320. Обновлена до 2026.10.19 в requirements и обеих поставках. Опасного emSign ECC Root CA - G3 в новом PEM нет. |
| S02 | Высокий, код + исполняемый файловый стенд | Mac installer повторно читал изменяемые script/plist после авторизации. Теперь root-сценарий фиксируется до диалога; plist создаётся самим root из UID с фиксированными аргументами и UserName, в закрытом staging; нестандартный ACL системного места установки отклоняется. |
| S03 | Высокий, граница привилегий + стенд | launchd stdio указывал в пользовательский каталог. Теперь `/dev/null`, включая rollback. Это исключает открытие подложенного пользовательского log-path до снижения привилегий. Технический Python-журнал остаётся у обычного пользователя. |
| S04 | Усиление Windows; статическая проверка | UAC получает сжатый снимок сценария через EncodedCommand; повышенный процесс использует только системный PSModulePath. Используются известные каталоги Windows, точные ACL, проверка владельца/reparse points, закрытый staging вместо наложения старых файлов, хеш всего пакета до UAC и владелец Administrators и закрытый ACL у каждого файла уже при CREATE_NEW, до записи содержимого. Удаление через LiteralPath и проверку дерева, без cmd.exe. Не объявляется подтверждённым исправлением эксплуатации на Windows без натурного запуска. |
| S05 | Средний, реальные локальные byte frames | poll() не ограничивал чтение оставшейся части IPC-кадра. Новый ipc_transport ограничивает весь кадр, длину, запись и авторизацию; поддерживает отмену. При завершении служба прерывает активные каналы до закрытия БД. На Windows предусмотрен CancelIoEx; исполнение требует Windows-проверки. |
| S06 | Средний, файловые фикстуры | POSIX профиль создаётся с правами 0700; на macOS расширенный ACL очищается через проверенный файловый дескриптор только у собственного профиля. Ключ открывается без следования symlink, проверяются владелец/права на POSIX, размер 32 байта и один hardlink; FIFO и другие специальные файлы отклоняются без блокировки открытия. Небезопасный ключ отклоняется. |
| S07 | Средний, точное воспроизведение | error_log сохранял первый RTMP path segment; там может быть ключ. Теперь весь путь удаляется. До исправления canary присутствовал в результате scrub, после отсутствует. |
| S08 | Средний, структурные мутации + 10 000 бинарных входов | Неверные типы Graphene дают SourceError; огромные/nonfinite числа отбрасываются. XML DTD/entity объявления отклоняются до разбора. WebSocket проверяет фрагменты и control frames. DNS имена, указатели, RDLENGTH и объём mDNS ограничены. |
| S09 | Средний, loopback slowloris | Requests socket timeout сбрасывался при каждом чтении, позволяя бесконечно передавать байты заголовка/тела. Добавлен общий watchdog HTTP-операций: он прерывает сокет, включая отделённый HTTP/1.0 body socket. Для speed и Graphene ограничено полное чтение блока. |
| S10 | Усиление HTTP и сборки | Speed не следует redirect внешнего источника. Legacy HTTP ограничивает чтение по времени и отвергает неоднозначный Content-Length/Transfer-Encoding. Windows builder проверяет пути, ссылки, размер архива и RECORD нового certifi wheel до замены. |
| S11 | Сопровождение цепочки поставки | Закреплены 8 прямых/транзитивных Python-зависимостей. CI actions закреплены на коммитах, permissions=contents:read, persist-credentials=false; добавлен pip-audit. Сам CI на GitHub этим поручением не запускался. |

Источник S01: [GHSA-6q48-6c7w-9gw2](https://github.com/certifi/python-certifi/security/advisories/GHSA-6q48-6c7w-9gw2).
Для использования дефектного CA-набора требуются дополнительные условия, описанные
в advisory; наличие затронутой версии не означает состоявшийся перехват данных.

## Доказательства и воспроизведение

- [До/после на сохранённых исходниках](https://github.com/mshnyrev13/vcs-network-watch): RTMP key, malformed Graphene, неправильная длина mDNS RDATA, XML DTD и повторное чтение Mac installer.
- [Инвентаризация](https://github.com/mshnyrev13/vcs-network-watch): версии Python, OpenSSL, Qt, libpcap и пакетов.
- Итоговые результаты, состав сборок и команды — [security/README.md](https://github.com/mshnyrev13/vcs-network-watch).
- `tests/test_security.py` использует только синтетические данные, socketpair, собственную IPC-службу и loopback HTTP. Тесты не устанавливают службу и не захватывают реальную сеть.
- `tests/test_security_installer.py` исполняет Mac shell-логику с подменёнными системными командами в временном дереве. Проверяет UID, fixed UserName/program, symlink/hardlink/owner refusal, rollback и изменение payload в момент имитации авторизации. Это не sudo/launchd-приёмка настоящей системы.

Проверка OSV после обновления не нашла известных записей для восьми зафиксированных
Python-пакетов. Это утверждение относится к дате проверки и базе OSV. Оно не
распространяется автоматически на Qt/C-код, ОС, Npcap и все используемые источники доверия.

## Разбор статических предупреждений

Bandit запущен по продуктовым Python-модулям; findings рассмотрены по месту вызова.
Первоначальный высокий B324 относился к SHA-1 в обязательном WebSocket Sec-WebSocket-Accept
(RFC 6455), а не к хешированию пароля. SQL B608 относится к подстановке фиксированных
таблиц/столбцов и SQL-фрагментов; пользовательские значения остаются параметрами.
B104 — намеренный локальный mDNS UDP listener, а HTTP/IPC не слушают внешний TCP.
B314/B405 — stdlib XML: DTD/entity декларации блокируются до ET.fromstring,
размер ответа ограничен. Предупреждения не скрывались глобальным nosec и не
объявляются уязвимостями только по результату сканера.

## Оставшиеся ограничения

1. Нет Windows-окружения для натурной проверки новых UAC/ACL/named pipe/CancelIoEx,
   NTFS гонок и доступа другого пользователя. Проверены код, синтаксис PowerShell,
   контрактные тесты и состав ZIP. Перед широкой Windows-поставкой нужен отдельный стенд.
2. Нет чистого Mac/второго пользователя. Реальные установка BPF, обновление launchd,
   запросы авторизации и Gatekeeper в этом этапе не выполнялись.
3. Mac ad hoc, без Developer ID/нотаризации; Windows launcher без подписи издателя.
   Снимок UAC/authorization устраняет повторное чтение после согласия, но не делает
   недоверенный изменённый пакет подлинным. Подпись и доверенный канал доставки остаются необходимы.
4. Нативные зависимости инвентаризированы; исходники CPython/Qt/OpenSSL/libpcap/Npcap
   не проходили собственный аудит/fuzzing с санитайзерами. Версия Apple libpcap 1.10.1
   сама по себе не устанавливает наличие/отсутствие исправлений Apple. Нужны обновления ОС.
5. Graphene применяет системное хранилище через truststore: состояние системных CA и
   отзывов не менялось. Новый certifi не является обновлением корневого хранилища macOS/Windows.
6. LLDP/mDNS не аутентифицируют топологию/источники. Захват намеренно даёт доступ к
   локальным кадрам; членство access_bpf также доступно другим процессам того же пользователя.
7. Фуззинг — детерминированный набор Python-парсеров, не исчерпывающий перебор всех
   пакетов. Нет независимого pentest, проверки всех сценариев IPC от администратора
   или гарантии защиты от процесса с теми же правами и ключом пользователя.

История, интервалы, выбор адаптера, ручной захват и политика очистки сохранены.
Пакеты, пользовательские настройки и ключи не отправлялись во внешние сканеры.
