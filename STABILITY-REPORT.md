# LinkRadar 2.10.0 — результат стабилизации

21 октября 2026. Локальная версия; публикация, установка и замена рабочей службы не выполнялись. Исходные изменения сохранены.

## Исправлено

- Текущие RTT и jitter больше не подменяются пиком графического bucket при смене масштаба. Карточки показывают конечный сервер; выбор hop меняет график. UI и экспорт используют один EWMA alpha=1/16; mean_delta — отдельная величина.
- Локальные DNS/route/access ошибки отделены от потерь отправленных проб. Нет свежих данных, ошибка измерения и недоступность цели различаются. Медленный последовательный traceroute использует фактический интервал узла для jitter.
- Маршрут hostname следует IP последнего ping: отдельный DNS не отправляет traceroute к другому балансируемому адресу. Запоздалые hops старого IP/адаптера не показываются как текущие. Привязка выбранного адаптера остаётся строгой, без fallback; скорость также использует выбранный NIC.
- Чтение SQLite отделено от writer. Таблица hops считается SQL, передаются только нужные графики и порции событий. RTT не пересортировываются после каждой вставки. Монотонный event cursor сохраняется после pruning/перезапуска без хранения самих удалённых событий.
- TXT/JSON передаются блоками с SHA-256, пишутся вне GUI атомарно; отмена и обрыв не заменяют прежний файл. Запись Graphene подтверждается до продвижения кэша; ошибка сохранения видна в интерфейсе и TXT.
- Исправлен плавающий отказ подключения IPC при записи скорости. Авторизация клиента ограничена по времени; зависший клиент не блокирует остальные подключения. Поддерживаются длинные пути профиля.
- Start/resume/clear сериализованы. Закрытие отменяет чтения и ждёт завершения потоков без зависания GUI. Поздние snapshot/PTR/Stream-результаты не восстанавливают старое состояние.
- Graphene повторно использует TLS-соединение и догружает хвост. Есть возврат к источнику LLDP, история сохраняется при отключении. Размер ответа ограничен во время чтения. Запрос каждые 5 с не ускоряет публикацию данных на стороне Graphene.
- Stream: один worker, свежесть источников, история стареет на паузе, известные OBS-сегменты не теряются; разрыв наблюдения указан в отчёте. Удалённый OBS/vMix не получает TCP-метрики локального энкодера. vMix API строго читает `/api` без управляющих параметров и redirects. DNS, TCP и чтение ограничены. URL-пароли, RTMP paths и SRT parameters удаляются до сохранения.
- Сохраняются только безопасные предпочтения окна, NIC, интервала и масштаба. Недоступный NIC не заменяется Auto. Есть выбор шлюза и журналы GUI/службы. Исправлены рост Windows lock-файлов, обработка пропущенного аргумента и защита CSV с ведущими control/whitespace.

Пики RAM измерены для тестовых процессов, это не обещание такого расхода всего GUI. Экспорт: клиент 33,6 МиБ, служба 47,6 МиБ; все записи и checksum проверены. Большой экспорт выполнен на промежуточной версии цикла; итоговые исходники дополнительно проходят регрессии и экспорт из собранного окна.

14 логических часов rollover: после заполнения осталось 86 400 ping и 1 296 000 hops; SQLite не выросла — 622 055 424 байта до/после. Это виртуальное время, не 14 часов непрерывной работы. Страницы переиспользуются; 12-часовой лимит не гарантирует небольшой файл при большом числе проб.

Нагрузочные циклы Qt 5 и 10 минут: синтетические 1 000 пакетов/с, 15 hops, ping 0,5 с. В 10-минутном цикле heartbeat P99 26,79 мс, максимум 58,3 мс, peak RSS 171,4 МиБ; CPU в отдельной выборке в среднем 6,24% одного ядра. Буфер удержался в 32 МиБ / <50 000 кадров; при закрытии все шесть измерительных таблиц пусты. Итоговый повтор 180,47 с: CPU 4,67%, peak RSS 164,6 МиБ, heartbeat P99 38,86 мс / максимум 53,39 мс; буфер ограничен, очистка успешна.

## Проверки

259 unit/integration-тестов: ошибок нет, 11 платформенных пропусков. Дополнительно 5 HTTP integration и 2 JavaScript-сценария, OK. Включены настоящий локальный HTTP/IPC, фикстуры OBS/vMix, отказ/обрыв экспорта, гонки pause/restart/clear, смена IP/NIC и IPv6 scope. Финальный Finder на публичных целях прошёл 7 этапов управления/экспорта и 80/80 ответов с завершённым 8-hop маршрутом; private packaged engine восстановился после SIGKILL с сохранением 5 проб и паузы, Finder через IPC получил 24 ответа шлюза. Проверены manifest/bytecode 31 модуля Mac, исходники 31 модуля Windows, CRC и зависимости; Windows не исполнялась. Полные результаты — [VALIDATION.md](VALIDATION.md). Машинные сводки — [stability-results.json](https://github.com/mshnyrev13/vcs-network-watch).

Системный ping до того же публичного IP в следующем замере: 12/12, median 9,9865 мс, max 87,574 мс. Это последовательная reference-проверка, не синхронное сравнение RTT и не проверка запущенного PingPlotter.

## Ограничения

- Windows ZIP проверяется структурно, но новая версия не исполнялась на Windows. Реальный USB и физическое переподключение позже прошли отдельную приёмку на этом Mac — [USB QA](https://github.com/mshnyrev13/vcs-network-watch). Другие USB-чипсеты не проверены.
- В отдельной USB-приёмке подтверждены живой IPv6, LLDP и Graphene. Живой эфир OBS/vMix не проверен. Доступная локальная IPv4-цель за USB не задана; отсутствие IPv4-шлюза ожидаемо по ответу пользователя.
- Захват на en0 проверен реальными кадрами без сохранения содержимого; полный внешний нагрузочный speed test не выполнялся. Успешный небольшой HTTPS-запрос не доказывает точность goodput на любой линии.
- Полный 12-часовой график занимает около секунды; частоту перерисовки 0,5 с для него не гарантируем. Запись новых ping не ждёт этот reader.
- macOS-сборка: Apple Silicon, macOS 15+, ad hoc подпись, без Developer ID и нотарификации. Финальный Finder из DMG к локальному шлюзу получил local_network_denied: новая сборка требует разрешения macOS «Локальная сеть». Эта попытка не прошла сетевую приёмку; при отказе доступов очистка/закрытие успешны. Права не менялись. Публичные цели и отдельный упакованный движок проверены, но не заменяют повтор Finder → шлюз после выдачи доступа. Чистый Mac/учётная запись также требуют проверки.
- В исходниках сохранён прежний веб-режим; основной контракт и приёмка относятся к настольному Qt. Большие server/desktop/Windows FFI остаются кандидатами на постепенное разделение; рискованный массовый рефакторинг не выполнялся.
- ICMP RTT jitter не равен jitter видео и сам по себе не гарантирует качество эфира. Транзитный hop может ограничивать ICMP-ответы без потерь конечного трафика.

На доступной среде подтверждённые существенные дефекты этого аудита исправлены. Не заявляется отсутствие ошибок в непроверенных сценариях. Следующий приоритет — приёмка Windows, другого оборудования, живого эфира и чистого Mac; для будущей поддержки добавлена CI-матрица, ещё не запущенная на GitHub.

Локальное ограничение снято для этого Mac; проверка чистого Mac остаётся. Подробности — VALIDATION.md.
