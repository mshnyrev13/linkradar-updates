# LinkRadar 2.10.7 — повторный аудит

21.10.2026, поверх опубликованной 2.10.6. Четыре исправительных прохода,
затем контроль данных, графиков и сборок. [Воспроизведение и журнал](https://github.com/mshnyrev13/vcs-network-watch).
Все нагрузочные и графические данные синтетические. Установленное приложение,
службы, сетевые настройки и рабочие профили не менялись; публикации нет.

## Исправления

1. На скрытой вкладке Network таймер запускал полное чтение выбранной истории,
   а скрытая Stream перестраивала таблицы и графики. Теперь периодическое
   построение вида выполняется для видимой вкладки. Измерения, TTL и уже
   запрошенная смена сервера продолжаются; показ вкладки сразу обновляет её.
   Кэш Stream освобождается при скрытии, история остаётся в движке. Захват
   пакетов сохраняет прежнее обслуживание 120-секундного буфера.
2. Отчёт Stream брал сетевые данные из последнего снимка интерфейса. Теперь
   при ручном создании отчёта читает текущий snapshot; ошибка чтения явно
   обозначается вместо молчаливого отсутствия раздела.
3. Оси и подсказки напрямую вызывали localtime, что на Windows может дать
   OSError для старой/повреждённой даты. Общий форматтер возвращает «—» для
   неподдерживаемого времени. Валидное время и миллисекунды пакета сохранены.
4. Stream записывал предсказуемый `report.txt.tmp`. Подготовленный hardlink
   воспроизвёл перезапись другого файла; ошибка replace оставляла временный
   отчёт. Теперь используется общий atomic_write: уникальное имя, fsync,
   атомарная замена и очистка собственного temp при ошибке.
5. Текстовые проверки используют UTF-8; Mac-only startup проверяется на Mac.
   Legacy integration учитывает необязательный TShark и отдельно проверяет
   управляемый отказ 400 при его отсутствии. Безопасность Windows ACL не ослаблялась.

## Проверка и ограничения

369 модульных тестов OK / 11 skipped; 6 локальных integration OK. Изображения
в восьми состояниях на 900×640, 1100×760, 1440×960: точные размеры, все видимые
блоки внутри окна. Дизайн не менялся без конкретного дефекта читаемости.
Подробности завершающего soak, HiDPI и упакованного запуска — в журнале round5.

Контрольная матрица ограничена доступной средой. Windows standalone, чистый Mac,
новая установка/запросы разрешений, реальный USB/коммутатор, OBS/vMix и ночной
прогон повторно не проверены. Предыдущие Windows CI проблемы ACL/геометрии
из CI-2.10.6.md требуют проверки в Windows. Наличие ZIP/manifest её не заменяет.
Условие остановки — отсутствие новых существенных дефектов в выполненном
контрольном проходе, а не утверждение, что приложение невозможно улучшить.


### Фактический запуск готовой Mac-сборки

App/DMG собраны, strict ad hoc codesign и состав read-only DMG проверены;
37 корневых модулей и 57 manifest inputs совпали с Mac bytecode и Windows ZIP,
CRC Windows ZIP успешен. Готовое окно 2.10.7 через Finder/LaunchServices
запустилось, отображало новые пробы и очистило шесть таблиц при закрытии.

**Ответы ICMP до loopback в этом проходе не подтверждены.** До 127.0.0.1 получены
таймауты как в 2.10.7 (6 проб), так и в неизменённой 2.10.6 (5 проб).
Системный /sbin/ping: 3 отправлено / 0 получено; ping6 ::1: 2 / 0.
Маршрут 127.0.0.1 указывает lo0. Точная причина на уровне ОС не установлена;
сетевые и защитные настройки не менялись. Первоначальный acceptance,
требующий ответов, завершился неуспешно и сохранён отдельно. Это ограничение
не подменено успешной проверкой связности; жизненный цикл с реальными
таймаутами проверен отдельным native_lifecycle.py.


Проверка жизненного цикла готового движка успешна: после SIGKILL сохранились
5 проб и пауза, продолжение дало 8 проб; Finder GUI подключился к этому
движку, увидел 13 проб и очистил сессию при закрытии. Это были реальные
таймауты, успешных ответов 0; network_verified=false сохранён в отчёте.


Дополнительная контрольная цель `ya.ru`: финальная готовая app через
Finder/LaunchServices получила **21/21 ICMP-ответ**, ошибок и потерь нет,
закрытие очистило измерения. Системный ping параллельно получил 3/3 ответа.
Общая доступность ICMP подтверждена на этой цели; ограничение относится к
loopback. RTT приложения 9,06–95,50 мс, средний 21,17 мс; системные три пробы
8,643–9,871 мс. Это разные выборки, равенство точности по их средним не заявляется.
Сырые снимки с сетевыми маршрутами остались только во временной диагностике;
в репозитории — агрегаты finder-public-target.json и system-public-target.json.
