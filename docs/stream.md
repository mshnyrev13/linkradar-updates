# Вкладка Stream

Состояние трансляций OBS и vMix: протоколы RTMP/RTMPS, SRT, NDI, выходы и записи. Только чтение. С версии 2.9.0.

## Запуск

1. Вкладка **Stream** → ▶. Опрос раз в секунду; ⏸ сохраняет историю.
2. OBS: включите Инструменты → Настройки сервера WebSocket. Для этого компьютера поле пароля можно оставить пустым: порт и пароль читаются из `obs-websocket/config.json` текущего пользователя и не сохраняются. Для другого компьютера укажите адрес, порт и пароль.
3. vMix: адрес веб-API (по умолчанию `http://127.0.0.1:8088/api`, Настройки → Web Controller). Для счётчиков потерь откройте окно vMix **Statistics** (значок с цветными столбиками справа внизу главного окна) — читается только на этом компьютере (Windows). vMix заполняет список Overview при открытии окна: после добавления входа переоткройте Statistics.
4. «Отчёт для провайдера»: кнопки **Копировать** и **Сохранить TXT…** справа вверху. Период отчёта = выбранный период графиков.
5. Столбцы таблиц: ширина меняется перетаскиванием границы в заголовке, двойной щелчок — по содержимому. При изменении окна все столбцы масштабируются в текущих пропорциях; заголовок не обрезается — в узком окне появляется горизонтальная прокрутка. Ширины не сохраняются между запусками. Подсказки к сокращённым заголовкам — при наведении.

## Источники

| Источник | Что даёт | Ограничения |
| --- | --- | --- |
| OBS, obs-websocket 5 (`GetStats`, `GetStreamStatus`, `GetRecordStatus`, `GetOutputList/Status`, `GetVideoSettings`, `GetStreamServiceSettings`) | состояние, длительность, байты → битрейт, потерянные сетью кадры, congestion 0–1, переподключения, FPS, пропуски рендера и кодировщика, CPU, сервер без ключа | OBS 28+; SRT-статистика libsrt (RTT/потери пакетов SRT) через WebSocket недоступна |
| vMix XML API | трансляция/запись/External/MultiCorder вкл/выкл, каналы, входы SRT/NDI/Stream | битрейта и потерь в API нет |
| Окно vMix Statistics (Win32 ListView) | Overview: Source/Renderer dropped, Resync, Queue, Fullscreen dropped и задержка выхода, аудиобуфер/потери/ресемплинг, `Connected ip:port` (если vMix его пишет); вкладка SRT: Bandwidth (mbps) → битрейт, Packet Loss (%), RTT (ms), Duration; Δ за секунду. Переименованный SRT/NDI-вход распознаётся по типу из API | окно должно быть открыто; читаются оба списка (Overview и SRT). Overview и заголовки SRT сверены с vMix 26.0.0.45; строки вкладки SRT вживую не видели (она была пуста при SRT-входе — вероятно, показывает SRT-выходы vMix) |
| TCP-соединения энкодеров (OBS, vMix, FFmpeg) | адрес ingest, протокол по порту (1935 RTMP, 443 RTMPS, 5960–5999 NDI); с ESTATS — битрейт, RTT, ретрансмиты | Windows; ESTATS включается только при запуске от администратора. HTTPS-соединения OBS/vMix показываются только во время эфира |
| NDI mDNS (`_ndi._tcp.local`) | имена и адреса источников NDI в сети | без NDI Discovery Server; статистики кадров NDI нет (кроме строк vMix Statistics) |

SRT по UDP не виден в таблице TCP; для SRT используются строки vMix Statistics и состояние выхода OBS.

Строки vMix 26 (сверено вживую): выход — `Output | 0 | 0 | 0 | 0 | Fullscreen Dropped: 4 0 14 (16 ms) |`; SRT-вход (listener, поток OBS) — `SRT  5000 | 14788 | 0 | 26 | 2 | 33 33 33 34 (144) | 120/40 ms Dropped: 24784/0 Resampled: 80/485720`. В колонке Video входа — интервалы кадров (33 мс при 30 fps) и число в скобках без единиц; оно не выдаётся за задержку. `Connected ip:port` у SRT-входа в режиме listener нет.

OBS после переподключения начинает `outputBytes`, кадры и длительность заново (сверено: OBS 32.1.2 → Twitch). Вкладка суммирует кадры и время в эфире в пределах одной трансляции; сброс счётчика байт во время эфира считается переподключением, даже если короткое состояние «переподключение» пришлось между опросами. После остановки в отчёте остаётся длительность последнего эфира.

ESTATS (от администратора): первое чтение после включения сбора пустое, данные — со следующего опроса. RTT замеряет только отправляющая сторона; до первого замера Windows отдаёт 0xFFFFFFFF — показывается как «нет данных». Через локальный VPN/TUN-прокси RTT отражает участок до прокси (на этом ПК 0–1 мс до Twitch, ретрансмитов 0); RTT ≤1 мс до внешнего адреса помечается в отчёте.

## Метрики и пороги

| Метрика | Смысл | Внимание / проблема |
| --- | --- | --- |
| Битрейт, кбит/с | фактическая отдача; сравнивать с заданным CBR | падения и пилы |
| Потеряно кадров, % | OBS «Dropped Frames (Network)» — сеть не успевает | ≥0,1% / ≥1% |
| Потери/с | рост счётчиков за секунду (OBS, vMix) | любое >0 — событие |
| Пропущено рендером / кодировщиком | нагрузка GPU/сцены или CPU/GPU кодировщика, не сеть | рост |
| Congestion 0–1 | заполненность буфера отправки OBS | ≥0,1 / ≥0,5 |
| RTT, мс (TCP) | задержка до ingest по TCP | ≥150 / ≥300 |
| Ретрансмиты, % | доля повторно отправленных сегментов | ≥1% / ≥3% |
| Переподключения | `outputReconnecting` OBS | каждое — событие |

Пороги — ориентиры для оператора, не оценка качества у зрителя.

## Отчёт для провайдера

Содержит: время в местном и UTC, период, компьютер, состояние источников; холст/вывод, FPS, CPU, пропуски рендера/кодировщика; по каждому потоку протокол, сервер без ключа, состояние, длительность, переподключения, битрейт сред/мин/макс, кадры и потери, congestion, TCP RTT и ретрансмиты; TCP-соединения энкодеров; NDI в сети; сеть с вкладки «Сеть» (адаптер, IP, шлюз, коммутатор/порт/VLAN, ICMP до сервера, маршрут, тест скорости); список событий.

Ключи потоков, пароли, логины из URL и параметры SRT (`streamid`, `passphrase`) не выводятся, не сохраняются и не экспортируются.

Перед отправкой провайдеру добавьте вручную: кодек/профиль, keyframe interval (обычно 2 с), режим битрейта (CBR), идентификатор трансляции у провайдера, симптомы у зрителей.

## Хранение

История и события — только в памяти, до 12 часов; не пишутся в SQLite и TXT-экспорт сессии «Сеть». Обычное закрытие окна останавливает опрос и очищает данные. Медленные источники (OBS, vMix API, mDNS) читаются в отдельных потоках: отказ соединения на localhost в Windows длится ~2 с и не задерживает остальные.

В 2.10.0 также вынесены в рабочие потоки TCP и Statistics. Во время завершения
кнопка запуска недоступна; второго опросчика не создаётся. Ответ от прежних
настроек отбрасывается. Отсутствие новых ответов отмечается отдельно от остановки
эфира; история продолжает стареть на паузе. Повторное отображение NDI не создаёт
фиктивных секундных измерений. URL в Statistics и ошибках очищаются до сохранения:
логины, пароли, параметры SRT и пути RTMP в отчёт не попадают. Из RTMP остаются
протокол, хост и порт: ключ может находиться уже в первом сегменте пути.


## Точность скорости потерь в 2.10.4

«Потери/с» и график показывают прирост счётчика кадров, делённый на фактическое
время между двумя свежими опросами. Например, 12 кадров за 4 с — 3 кадра/с.
История и отчёт за период по-прежнему суммируют исходное количество кадров.
vMix Statistics показывает «Δ за опрос»: это количество, а не скорость.
После паузы, смены настроек или закрытия окна Statistics нужна новая пара
замеров; потери за ненаблюдаемый промежуток к текущему интервалу не относятся.
Сброс счётчика не даёт отрицательных потерь; при нулевом времени скорость неизвестна.
