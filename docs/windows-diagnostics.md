# Исправления диагностики Windows

Проверки 23–25 ноября 2026. Изменения вошли в
[LinkRadar 2.10.14](https://github.com/mshnyrev13/linkradar-updates/releases/tag/v2.10.14).

## Поведение

- Сеть и Stream: ползунок истории, стрелки/PageUp/PageDown/Home/End и кнопка
  «Сейчас». Справа продолжается слежение за измерениями. Выбранная история
  остаётся на месте во время сбора. Zoom меняет период; срок хранения 12 часов.
- Windows: Graphene скрыт, таймеры и запросы по объявлениям LLDP остановлены.
  На macOS Graphene сохранён.
- Подробности пакета: кнопка «Закрыть подробности ×»; обновление таблицы не
  открывает панель заново. Повторный щелчок по тому же пакету открывает её.
- Speedtest показывает отдельный ICMP Ping до сервера CDN без запуска основной
  сессии. Привязка адаптера сохраняется. Отсутствие ICMP-ответа не заменяется нулём.
- Плотные графики сокращаются до детализации экрана с extrema и разрывами.
  Полные данные, статистика и экспорт не сокращаются. Перья QPainter переиспользуются.
- При наведении на график вертикальная линия показывает время под курсором
  внизу. Подсказка сохраняет время и значения ближайшего измерения.

## RTMP vMix

Учитываются `ffmpeg.exe`, `ffmpeg2.exe` и `ffmpeg6.exe` из установленного vMix. Исправлено
застывание связанного TCP-битрейта после первого значения. Читаются числовые
поля свежих журналов FFmpeg из `C:\ProgramData\vMix\streaming` без повышения прав.
Отдельные строки «vMix · Энкодер N» показывают битрейт и FPS. При одном свежем
канале его битрейт также доступен у локальной трансляции XML API.

Читаются только последние 64 КиБ файла; TTL — 10 секунд. Команды, адреса,
ключи, сырые строки и имена файлов не сохраняются и не экспортируются.
Неподвижная строка не создаёт повторных точек. После исчезновения данных
метрики очищаются. Данные локального журнала не привязываются к удалённому API.

Это средний битрейт кодировщика. Журнал не сообщает TCP RTT, сетевые потери
кадров или OBS congestion. Для этих показателей требуются соответствующие
источники: Statistics или TCP EStats. Отсутствующие показатели остаются пустыми.

Формат и назначение журнала подтверждены
[документацией vMix](https://www.vmix.com/knowledgebase/article.aspx/140/understanding-ffmpeg-streaming-logs).

## Проверки

Windows, Python 3.11, PySide6 6.12, Fusion/STYLE, отдельные временные профили:

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python tests/integration_local.py
node tests/test_start_stop.js
node tests/test_stream_analysis.js
```

Новые регрессии: `tests/test_diagnostics_feedback.py`.
Нативные проверки: реальные ICMP loopback, HTTP speedtest, локальный RTMP
установленным `ffmpeg2.exe` из комплекта vMix, чтение его progress-строк,
навигация мышью, окна 900×640/1100×760 и закрытие подробностей TCP-фикстуры.
Результаты и скриншоты хранятся отдельно от Git.

Сравнение плотного графика 360×250 (медиана 20 отрисовок):

| История | До | После |
| --- | ---: | ---: |
| 15 минут, 1800 проб | 10,53 мс | 7,62 мс |
| 12 часов, 86400 проб | 46,70 мс | 19,14 мс |

В таблице замерено только время отрисовки. Первичный короткий RTMP-тест
использовал отдельный локальный приёмник и синтетический видеосигнал.
OBS WebSocket в этом прогоне проверялся регрессионными фикстурами. После
восстановления запуска vMix выходы проверены из его интерфейса.

Маркер времени отдельно проверен в нативном окне Windows на графиках ICMP
и локального RTMP с FFmpeg 6. Проверены смена масштаба, обновление при
поступлении точек и скрытие маркера при уходе курсора. Итоговый локальный
unit-прогон завершился успешно (445 тестов, 32 пропущены).

## Живой vMix 28.0.0.42

Дополнительная проверка 23 ноября 2026 после восстановления запуска vMix:
API, главное окно, Statistics Overview/SRT/Encoders и настоящие потоки из UI.
RTMP FFMPEG запустил установленный ffmpeg2.exe, FFMPEG6 — ffmpeg6.exe.
Локальный приёмник декодировал 720p/29,97 FPS H264 и AAC; LinkRadar получал
примерно 2,55–2,62 Мбит/с и 29–30 FPS. TCP ESTATS в этом запуске недоступны,
поэтому RTT и ретрансмиты RTMP остаются неизвестными.

Нативный SRT Caller Output 1 передавал H264/AAC в MPEG-TS через libsrt 1.5.4
локальному listener. Полученный материал декодирован как 1080p/29,97 FPS.
Statistics показывал около 2,42–2,43 Мбит/с, Packet Loss 0%, RTT 0 мс;
LinkRadar получил те же значения с преобразованием Мбит/с → кбит/с.
Caller и Listener проверены с отключением и повторным подключением.
В длительном прогоне LinkRadar собрал 832 отдельных метрики SRT за 15 мин 38 с.
Это реальная передача внутри ПК с синтетическим видеосигналом. Качество
внешнего канала, NAT, шифрованный SRT и YouTube ingest этим не проверены.

Обнаружены и исправлены дополнительные ошибки:

- Encoders имеет Source «Output 1», который старый разбор превращал в одну
  потерю кадра. Теперь этот тип таблицы отделён от Overview.
- Скрытая SRT-таблица оставалась на прежней Duration/Total Data, хотя поток
  продолжался. Теперь читается только видимая таблица, без фиктивных свежих точек.
- Пустая открытая таблица отличается от закрытого окна Statistics.
- Отчёт подписывает SRT RTT отдельно от TCP; подсказки учитывают источник.
- Явное Disconnected у SRT в Overview показывается как «нет соединения»,
  а не «подключено»; восстановление Connected возвращает активное состояние.

Краткий тайм-аут чтения Overview иногда убирает активную строку и записывает
«источник больше не виден». После успешного опроса строка возвращается.
Для сетевых метрик SRT держите открытой вкладку Statistics → SRT. После
смены выхода нажмите **Refresh**.
